# -CH04 데이터 모델링-
**데이터 모델링(modeling)** :현실 세계에 존재하는 데이터를 컴퓨터 세계의 데이터 베이스로 옮기는 과정,change->데이터 베이스에 저장할수 있는 구조로!  db설계에서 가장 핵심 적인 단계.
예시: 김철수 학생이 db 수업 수강함 -> 학생(김철수) , 강의(데이터 베이스) 이런 방식으로 바꾸는것. 
****

**데이터 모델링은 2단계로 분류**
**개념적 데이터 모델링(conseptual)**:현실세계 중요데이터 추출,개념세계로 옮기기~
**논리적 데이터 모델링(logical)**:개념세계 데이터->실제 데이터 베이스 저장 구조로~
****
**데이터 모델이란?**:데이터 모델링을 통해 만든 **설계결과물.**
-종류 두가지-
**개념적 데이터 모델:** 사람이 이해하기 쉬운 개념으로 표현, 예)e-r모델. 
**논리적 데이터 모델:** 실제 db에 적용가능한 구조. 예)관계 데이터 모델.
학생의 정보 기준.
ER 모델: 개념적 데이터 추상화.번호- [학생]-이름
테이블 형태: 논리적 데이터 모델 (관계형) 학생|번호|이름.
****
### -CH04-02 데이터모델의 구성.
**-데이터구조(structure)** 
-개념적 구조: 현실세계->개념세계 추상화 할떄 **어떤 요소로 이루어 져있는지.**
-논리적 구조:데이터를 **어떤 모습으로 저장할 것인지.**
**-정적특징:**자주 변하지 않음.

**-연산**:표현된 값을 어떻게 처리할 것인지.
**동적특징::** 실제 데이터는 연산에 의해 계속 변경이 가능함.

**-제약조건**:데이터 정확성,일관성 무결성 유지 목적 .
****
### Ch04-03 데이터 베이스 설계과정.
-1단계:개념적 설계: 현실세계의 데이터를 E-R모델로 표현.
-2단계:E-R모델을 관계형모델(릴레이션) 즉 테이블 형태로 변환.
-3단계:DBMS 구현: 실제 데이터 베이스를 소프트 웨어에 적용.

DBMS는 E-R모델을 왜 직접 사용하지 않을까? **왜냐하면 DBMS는 논리적 구조만 처리가 가능하기 때문이다.따라서 e-r모델을 릴레이션 스키마로 변환해야한다.**
****

**계체-관계 모델.(E-R model)**
현실 세계를 개체(Entity) 관계(Relationship)로 표현.
피터첸이 제안함.
**핵심요소: 개체(Entity):사람 사물,  속성(Attribute):개체의 특징 관계(Relationship):계체들 간의 연관성.**
-계체:직사각형 관계:마름모.
E-R 다이어그램이란? -계체 관계 모델을 시각적으로 도식화 한것 즉 모델링한 결과를 그림으로 표현한것.
****
**개체(entity):** 현실세계에 존재하는 사람,사물,개념,사건.추상적/개념적으로 실체하는 무형의 정보.
-조건-
-보통 이름으로  구별 가능해야함.
-저장할 가치 있는 정보를 포함해야함.
-속성을 하나 이상 가짐.
예시)서점에 필요한 개체:고객,책. 
-파일 구조의 record와 대응됨:인스턴스 한줄,데이터 한줄 ROW.
-E-R다이어 그램에서 사각형으로 표시.그리고 안에 이름.
****
**속성(attribute):** 개체의 특성이나 상태 즉,개체의 상세정보를 표현. 예시)이름,등급,적립금.
-속성값? 개체의 특성이나 상태가 현실화한 값 ex)홍길동,정회원 ,12300.
-속성은 개체 또는 관계의 고유한 특성이다.
-가장 작은 단위의 의미있는 정보이다.
-파일 구조로 말하면 **필드(field에)** 해당된다.
-E-R다이어 그램에서 타원형으로 표시.
**식별자(Identifier):** 각 개체 인스턴스(스키마의 값)을 유일하게 **식별** 해줄수 있게 하는 **속성**.
보통 이후에 나오는 **기본키(primaryKey)** 로 사용된다.
-식별자는 중복되면 안디고,모든 인스턴스를 구별가능 해야 함.   
-E-R다이어그램에서 식별자 표현법:밑줄을 그어서 표시함.
****
개체-관계 모델.
개체 타입(Entity Type)
같은 속성 구조를 공유하는 개체의 틀.
개체를 고유한 이름 으로 정의한것.
파일 구조의 Record type=즉 하나의 행 을 담당함. ex)학생이라는 타입은 이름,학번,전화번호 속성을 가진다. 이렇게 구조를 정의한 하나의 행,을 이루는 것이다. 
****
개체 인스턴스(Entity instance)
정의 된 구조에 실제 값을 넣은것,말 그대로 인스턴스. 실제 데이터를 가진 개체 한명 한명 ex)김민수 학생.
개체 어커런스 라고도 한다. 
구조가 아닌 실제 데이터가 담긴 행이니 레코드 인스턴스에 해당된다.
****
개체 집합(entity set)
특정 개체 타입에 대한 개체 인스턴스를 모아 놓은 것. 즉 같은 타입을 가진 인스턴스 들의 모임 (예:전체 학생들)
****
속성(attribute)은 이러한 기준으로 분류도 가능하다..
속성값의 개수: 단일값|다중값.
의미의 분해가능성:단순|복합.
기존 속성 값에서 유도: 유도 속성.
****
**단일값속성[single-valued attribute]:** 하나의 값만 가질수 있는,저장할수 있는 속성 예시)고객한테는 이름도 하나고,적립금도 하나다.
**다중값속성[multi-valued attribute]:** 값을 여러개 가질수 (저장할수) 있는 속성. 예시)고객의 연락처(집,휴대폰) 책개체의 저자.  e-r다이어그램에서는 이중 타원형 으로 표시한다.-동그라미가 두개~
****
**단순 속성(simple attribute):** 더이상 나눌수 없는,분해할수 없는 속성 즉 하나의 값만 저장 할수 있는 속성. 논리적으로 분해가 불가능한,예시 )고객의 적립금,은 더이상 나눌수 없는 속성이다.
**복합 속성(Composite Attribute):** 여러 속성으로 세분화 가능한 속성. 예시)고객의 주소 같은것. [도,시,동] 같은 걸로 세분화가 가능함. 생년월일 역시 [연,월,일] 가능.
E-R다이어 그램에서 복합속성은 타원에서 다시 선이 갈라져서 다시 타원으로 세부 항목을 표현한다.
****
**유도속성(Derived):** 다른 속성의 값들로 부터 계산할수 있는 속성. 필요할떄 마다 계산되므로 db에 별도로 저장되지 않는다.
e-r다이어 그램에서는 점선 타원으로 표시된다. 
예시)책 개체의 가격과 할인율 속성으로 계산되는 판매 가격 속성.(원가 x(1-할인율))
예시)고객 개체의 출생연도 속성으로 계산되는 나이 속성.(현재연도-출생연도)
****
**널(null)값:** 아직 결정되지 않았거나,모르는값,존재하지 않는 값. 즉 단순한 공백이나 0이 아니다!!!
**널(null)속성:** 단순하게 널 값이 허용 되는 속성.예시) 취미 필드를 비울수 있다면 널 속성.
****
**키속성(key Attribute):** 각 개체 인스턴스를 식별하는데 사용 되는 속성이다.
모든 개체의 인스턴스는 키 속성 값이 다름. 예시)고객-키속성:고객id 학생-키속성:학번.
모든 인스턴스가 고유한 값을 가져야함.
키는 하나의 속성 또는 복합 속성 일수도 있음.
e-r다이어그램에서는 밑줄로 표현한다.
****
**관계(relationship):** 마름마름모.다이아몬두.
개체와 개체가 맺고 있는 의미있는 연관성. 즉 매핑(mapping)를 의미한다.
**관계 카디낼리티(관계차수)** 는 하나의 관계에 실제로 참여할수 있는 인스턴스 수.
****
**계체관계 다이어그램(Entity-Relationship)다이어그램:** 의 세가지 구성요소:
엔티티 집합(entity set): 같은 유형의 개체들을 묶은것,유사한 엔티티들의 집합. 엔티티는 객체에 해당.
애트리뷰트(attribute):속성,타원형 엔티티의 특성을 기술하는 값.
관계성(Relationship):둘 이상 엔티티 집합들간의 연결. 개체들 간의 의미있는 관계 마름모,다이아몬드로 표시.
****
E-R다이어그램의 인스턴스(instance)-즉 데이터에 실제로 들어가는 값. 
E-R다이어그램은 데이터베이스의 구조 즉 스키마를 표현할 뿐이다.
인스턴스로 스키마의 특정한 값들이 배정되는것이다.
예시)stars-in의 관계성의 인스턴스면
Movies:토탈리콜 stars:샤론스톤. 이렇게 실제로 들어가는 값이다.
****
관계의 유형? :관계에 참여하는 개체타입의 수 기준이다.
이항관계: 릴레이션 한개에 개체타입 2개. 
삼항관계: 릴레이션 한개에 개체타입 3개. 
순환관계: 릴레이션 한개와 개체타입 1개가 서로서로,즉 자기 자신과 맻는 관계.
****
관계의 유형: **매핑 카디널리티** 기준.
매핑카디널리티:개체 a와 b사이에서 한 인스턴스가 몇개의 상대와 관계를 맺을수 있는지. 관계를 맻는 두 개체 집합 
엔티티 집합에서 각 개체 인스턴스(값이) 연관성을 맻고 있는 상대 개체 집합의 인스턴스 개수.
-종류-
1대1관계.
일대다(1:N)관계.
다대다(N:M)관계.
****
**1대1관계:** 개체a의 인스턴스 1개 <-> 개체b의 인스턴스 1개  즉 하나의 관계만, 남편과아내 같은 혼인 관계. 사람 주민등록 번호처럼..
**일대다(1:n)관계:**개체a의 인스턴스 1개 <-> 개체b의 인스턴스 여러개. 즉 a는 b와 여러개의 관계가 가능하다. 예시)학과->과목. 한 학과는 여러개의 과목을 개설 가능함,컴공인 경우에도 자료구조,디비 등등...
**다대다(n:m)관계:** 개체 a의 인스턴스와 개체b의 인스턴스가 서로서로 여러개의 관계가 가능한 구조.
예시)고객<->책:고객은 책을 여러개 구매할수있고 책 역시 여러 고객한테 판매될수 있음.
학생<->과목:한 학생은 여러 과목 수강 가능 한과목도 여러 학생이 수강가능.
****
**관계의 참여특성.** 관계의 개체가 얼마나 꼭 참여해야하는가,이중선으로 표현.
필수적 참여:모든 개체 인스턴스가 관계에 반드시 참여해야하는것.다이어 그램에서는 이중선으로 표시한다.
ex)고객과 책 개체 와의 구매 관계는 필수적으로 참여해야한다.
이유:고객이 책을 구매해야 관계가 연결이 되기 때문에.
선택적 참여: 개체 인스턴스중 일부만 관계에 참여해도 되는것을 의미한다. 
ex)책 개체가 고객개체와의 구매관계에 선택적으로 참여한다. 왜냐면 고객이 구매하지 않은 책이 존재하기 떄문.
****
**관계의 종속성**
약한개체(week):다른 개체가 존재해야만 함꼐 존재할수 있는 개체.이중 사각형으로 표시한다.
강한개체(strong):독립적으로 존개가능한 개체.
강한 개체와 약한개체는 일반적으로 1:n 관계.
약한 개체는 강한개체에 필수적으로 참여한다. 
약한 개체는 강한개체의 키를 포함하여 키를 구성한다.
약한 개체가 강한 개체와 맺는 관계는 이중 마름모로 표현한다.
예시)직원-강한개체 부양가족-약한개체(직원이 없으면 존재 의미가 없음.) 그래서 이러한 관계는 또 이중 마름모로 표현.
****
**정리**
사각형: 개체(entity) 약한 개체는 이중으로..
마름모: 관계(relationship) 약한개체가 강한 개체와 맺는 관계는 이중 마름모로..
타원:속성(attribute)을 표현한다.다중값은 이중으로 유도속성(Derived)는 점선으로 표현한다.
링크(연결선): 각요소를 연결한다. 
레이블:일대일,일대다,다대다, 관계를 표기한다.
****
**다중방향관계성(multiway)관계성:** 세개이상의 엔티티 즉 사각형들이 하나의 마름모(attribute)에 동시에 참여하는 경우다.
예시를 따지자면     [마름모:계약]에 [사각형:스타] [사각형:영화] [사각형:계약] 이런 방식이다.
그러나 다중 방향 관계성은 그리 흔하지 않다. 이진(binary) 관계성이 흔하다.
****
**관계성에서의ROLE:** 한 엔티티집합(entity) 사각형이 한 관계성에서 두번 이상 사용가능한 것이다.
즉 동일 개체[사각형]이 한관계[마름모]에 두번이상 참여가 가능한거다.
이경우 개체[엔티티 사각형]은 각라인으로 서로 다른 역할을 수행한다.
[사각형:영화]-오리지널-> [관계:후속편]

**논리적 데이터 모델의 개념**
이제 개념적 구조로 e-r다이어 그램을 그렸으니 이걸 어떻게 데이터베이스에 저장할지 논리적으로 구조화하여 설계하는것.
데이터베이스에서의 논리적 구조는 = 데이터베이스 스키마(schema)다.
사용자가 인식하는 테이블/관계구조의 데이터베이스 모습 또는 구조이다.
대표적예시)관계형[Relational] 계층형[Hierarchical] 네트워크[Newwork] 모델
****
**관계데이터모델**
일반적으로 가장 많이 사용하는 논리적 데이터 모델. 오라클,sql,db2등등.
데이터표현:table. 즉 행과 열.
포인터가 아닌 속성값을 이용한다.
장점:개념 이해가 빠르고,프로그램 개발이 빠르다.
단점: 포인터를 이용하는 방법보다 검색 속도가 다를수도 있다.
예시)학과 테이블: 학과 id 학과명
학생테이블: 학번,이름,학과id.
수강테이블: 학과,과목id .

**계층형데이터관계모델.(Hierarchical)**
논리적 구조:트리 형태.
루트 역할하는 개체 존재 사이클 없음.
관계 구조: 부모 자식 구조만 가능 즉 1:n.
관계수: 각개체당 하나의 관계만.
장점:포인터 개념 이용이라 검색 속도는 빠르다.
단점:다대다 관계 표현 불가능,구조 변경 어려움.
즉 복잡한 현실을 담기에는 제약이 좀많다.

**네트워크 데이터 모델(Newwork)**
데이터베이스의 논리적 구조가 네트워크,즉 그래프 형태임.
개체는 직사각형 관계는 화살표.
개체간에는 일대다 (1:n) 관계만 허용된다. 오너/멤버.
두개체 간의 관계를 여러개 정의할 수 있어 이름으로 구별한다.(관계)
그러나 다대다 관계를 직접 표현 못한다.
구조가 복잡하고 데이터의 삽입 삭제 수정 검색이 쉽지않음. 
1960년대 GE IDS.
사이클 허용 포인터 기반, 관계를 나타내는 화살표에 이름 필요. 
장점:포인터 이용해서 빠름.관계 두개이상 표현 가능해서 계층보다 자연스러움
단점: 구조가 복잡,레코드 구조 변경 어려움, 응용프로그램 수정하기 어려움.

**attribute로 모델하는것이 바람직한 조건**
1.관계는 모두 one-to-many. 엔티티집합은 다른 개체들과의 관계에서 항상 many쪽에 있어야함.
2.엔티티 집합의 속성들은 모두 상호 독립적 속성간 종속성이 없어야함.
3.엔티티 집합이 두번 이상 참가하는 관계성이 없어야함. 즉 자기참조금지.
위 조건들이 일치하면 엔티티 집합을 에트리뷰트로 전환가능.

**실제로 엔티티 집합을 에트리뷰트로 변환해보자**
엔티티 집합 E와 연관된 관계성을 R이라 하자.
관계성 R이 이진 관계성인 경우. E와 R을 제거하고  E의 에트리뷰트를 r과 관련된 다른 엔티티 집합 f로 이동한다.
즉 스튜디오 엔티티를 제거한후 영화 엔티티에 스튜디오 이름이랑 스튜디오 주소 속성을 추가하는거다.

**제약(Constraint)**
현실 세계를 올바르게 나타낼수 있도록 데이터베이스를 유지.
제약의 분류:key,single-value(단일값),referential intergrity(참조 무결성),domain도메인,general일반.
****
**key**
E:엔티티 집합.
키:하나 이상 애트리뷰트의 집합 k.
즉 학생의 학번,도서의 isbn은 절대로 애트리뷰트가 중복되면 안됨,동일한값x 다이어그램에서 밑줄로 표시된다.

isa 계층구조에서 키를 구성하는 모든애트리뷰트는 모두 root 엔티티 집합에 존재.
****
**단일값 제약**
많아야 하나의 값만 가질수 있다는 제약.
단일값을 가지는 애트리뷰트:애트리뷰트의 값이 반드시존재해야하는 경우-키라던가.
에트리뷰트이 값이 있거나 없을수도 있는 경우, 널값이 사용된다.
널이 될수 있다는 표기법은 별도로 없다.
many-one 관계성. e->f 인경우 엔티티 e는 단일값 제약.
****
**참조무결성제약**
관계성에 참조되는 엔티티는 반드시 존재해야한다.
관계성 owns인경우 :엔티티 집합 무비로부터 스튜디오로.
즉 스튜디오 개체가 반드시 존재해야하며 영화는 둘이상의 스튜디오에 소유될수 없다는것을 의미.
어떤테이블의 외래키는 반드시 다른테이블의 기본키를 참가해야함.
수강테이블에서 학번은 학생테이블의 학번을 참조하는것 처럼...
참조되는 객체의 삭제 금지. 다이어그램에서는 둥근 화살표 =1을 의미한다..
