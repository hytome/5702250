# -CH04 데이터 모델링-
**데이터 모델링(modeling)** :현실 세계에 존재하는 데이터를 컴퓨터 세계의 데이터 베이스로 옮기는 과정,change->데이터 베이스에 저장할수 있는 구조로!  db설계에서 가장 핵심 적인 단계.
예시: 김철수 학생이 db 수업 수강함 -> 학생(김철수) , 강의(데이터 베이스) 이런 방식으로 바꾸는것. 
****

**데이터 모델링은 2단계로 분류**
**개념적 데이터 모델링(conseptual)**:현실세계 중요데이터 추출,개념세계로 옮기기~
**논리적 데이터 모델링(logical)**:개념세계 데이터->실제 데이터 베이스 저장 구조로~
****
**데이터 모델이란?**:데이터 모델링을 통해 만든 **설계결과물.**
-종류 두가지-
**개념적 데이터 모델:** 사람이 이해하기 쉬운 개념으로 표현, 예)e-r모델. 
**논리적 데이터 모델:** 실제 db에 적용가능한 구조. 예)관계 데이터 모델.
학생의 정보 기준.
ER 모델: 개념적 데이터 추상화.번호- [학생]-이름
테이블 형태: 논리적 데이터 모델 (관계형) 학생|번호|이름.
****
### -CH04-02 데이터모델의 구성.
**-데이터구조(structure)** 
-개념적 구조: 현실세계->개념세계 추상화 할떄 **어떤 요소로 이루어 져있는지.**
-논리적 구조:데이터를 **어떤 모습으로 저장할 것인지.**
**-정적특징:**자주 변하지 않음.

**-연산**:표현된 값을 어떻게 처리할 것인지.
**동적특징::** 실제 데이터는 연산에 의해 계속 변경이 가능함.

**-제약조건**:데이터 정확성,일관성 무결성 유지 목적 .
****
### Ch04-03 데이터 베이스 설계과정.
-1단계:개념적 설계: 현실세계의 데이터를 E-R모델로 표현.
-2단계:E-R모델을 관계형모델(릴레이션) 즉 테이블 형태로 변환.
-3단계:DBMS 구현: 실제 데이터 베이스를 소프트 웨어에 적용.

DBMS는 E-R모델을 왜 직접 사용하지 않을까? **왜냐하면 DBMS는 논리적 구조만 처리가 가능하기 때문이다.따라서 e-r모델을 릴레이션 스키마로 변환해야한다.**
****

**계체-관계 모델.(E-R model)**
현실 세계를 개체(Entity) 관계(Relationship)로 표현.
피터첸이 제안함.
**핵심요소: 개체(Entity):사람 사물,  속성(Attribute):개체의 특징 관계(Relationship):계체들 간의 연관성.**
-계체:직사각형 관계:마름모.
E-R 다이어그램이란? -계체 관계 모델을 시각적으로 도식화 한것 즉 모델링한 결과를 그림으로 표현한것.
****
**개체(entity):** 현실세계에 존재하는 사람,사물,개념,사건.추상적/개념적으로 실체하는 무형의 정보.
-조건-
-보통 이름으로  구별 가능해야함.
-저장할 가치 있는 정보를 포함해야함.
-속성을 하나 이상 가짐.
예시)서점에 필요한 개체:고객,책. 
-파일 구조의 record와 대응됨:인스턴스 한줄,데이터 한줄 ROW.
-E-R다이어 그램에서 사각형으로 표시.그리고 안에 이름.
****
**속성(attribute):** 개체의 특성이나 상태 즉,개체의 상세정보를 표현. 예시)이름,등급,적립금.
-속성값? 개체의 특성이나 상태가 현실화한 값 ex)홍길동,정회원 ,12300.
-속성은 개체 또는 관계의 고유한 특성이다.
-가장 작은 단위의 의미있는 정보이다.
-파일 구조로 말하면 **필드(field에)** 해당된다.
-E-R다이어 그램에서 타원형으로 표시.
**식별자(Identifier):** 각 개체 인스턴스(스키마의 값)을 유일하게 **식별** 해줄수 있게 하는 **속성**.
보통 이후에 나오는 **기본키(primaryKey)** 로 사용된다.
-식별자는 중복되면 안디고,모든 인스턴스를 구별가능 해야 함.   
-E-R다이어그램에서 식별자 표현법:밑줄을 그어서 표시함.
****
개체-관계 모델.
개체 타입(Entity Type)
같은 속성 구조를 공유하는 개체의 틀.
개체를 고유한 이름 으로 정의한것.
파일 구조의 Record type=즉 하나의 행 을 담당함. ex)학생이라는 타입은 이름,학번,전화번호 속성을 가진다. 이렇게 구조를 정의한 하나의 행,을 이루는 것이다. 
****
개체 인스턴스(Entity instance)
정의 된 구조에 실제 값을 넣은것,말 그대로 인스턴스. 실제 데이터를 가진 개체 한명 한명 ex)김민수 학생.
개체 어커런스 라고도 한다. 
구조가 아닌 실제 데이터가 담긴 행이니 레코드 인스턴스에 해당된다.
****
개체 집합(entity set)
특정 개체 타입에 대한 개체 인스턴스를 모아 놓은 것. 즉 같은 타입을 가진 인스턴스 들의 모임 (예:전체 학생들)
****
속성(attribute)은 이러한 기준으로 분류도 가능하다..
속성값의 개수: 단일값|다중값.
의미의 분해가능성:단순|복합.
기존 속성 값에서 유도: 유도 속성.
****
**단일값속성[single-valued attribute]:** 하나의 값만 가질수 있는,저장할수 있는 속성 예시)고객한테는 이름도 하나고,적립금도 하나다.
**다중값속성[multi-valued attribute]:** 값을 여러개 가질수 (저장할수) 있는 속성. 예시)고객의 연락처(집,휴대폰) 책개체의 저자.  e-r다이어그램에서는 이중 타원형 으로 표시한다.-동그라미가 두개~
****
**단순 속성(simple attribute):** 더이상 나눌수 없는,분해할수 없는 속성 즉 하나의 값만 저장 할수 있는 속성. 논리적으로 분해가 불가능한,예시 )고객의 적립금,은 더이상 나눌수 없는 속성이다.
**복합 속성(Composite Attribute):** 여러 속성으로 세분화 가능한 속성. 예시)고객의 주소 같은것. [도,시,동] 같은 걸로 세분화가 가능함. 생년월일 역시 [연,월,일] 가능.
E-R다이어 그램에서 복합속성은 타원에서 다시 선이 갈라져서 다시 타원으로 세부 항목을 표현한다.
****
**유도속성(Derived):** 다른 속성의 값들로 부터 계산할수 있는 속성. 필요할떄 마다 계산되므로 db에 별도로 저장되지 않는다.
e-r다이어 그램에서는 점선 타원으로 표시된다. 
예시)책 개체의 가격과 할인율 속성으로 계산되는 판매 가격 속성.(원가 x(1-할인율))
예시)고객 개체의 출생연도 속성으로 계산되는 나이 속성.(현재연도-출생연도)
****
**널(null)값:** 아직 결정되지 않았거나,모르는값,존재하지 않는 값. 즉 단순한 공백이나 0이 아니다!!!
**널(null)속성:** 단순하게 널 값이 허용 되는 속성.예시) 취미 필드를 비울수 있다면 널 속성.
****
**키속성(key Attribute):** 각 개체 인스턴스를 식별하는데 사용 되는 속성이다.
모든 개체의 인스턴스는 키 속성 값이 다름. 예시)고객-키속성:고객id 학생-키속성:학번.
모든 인스턴스가 고유한 값을 가져야함.
키는 하나의 속성 또는 복합 속성 일수도 있음.
e-r다이어그램에서는 밑줄로 표현한다.
****
**관계(relationship):** 마름마름모.다이아몬두.
개체와 개체가 맺고 있는 의미있는 연관성.
**관계 카디낼리티(관계차수)** 는 하나의 관계에 실제로 참여할수 있는 인스턴스 수.
