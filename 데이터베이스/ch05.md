## ch05 관계 데이터 모델링
****
**관계데이터모델링:** 개념적->논리적 구조로 표현하는 논리적 데이터 모델.
하나의 개체에 관한 데이터를 하나의 릴레이션에 저장.
**릴레이션:** 수학적으로는 두개이상의 집합으로부터 각집합을 구성 원소들의 순서쌍에 대한 집합을 의미.
회원명:{송중기,서현,송혜교,보아}
주소 = {서울 강남, 서울 용산, 서울 구로, 경기 용인}
{(송중기,서울 강남),(서현 서울 용산)..}이런 방식.
****
**Relation:** 하나의 개체에 대한 데이터를 행과 열로 구성된 2차원 테이블 구조로 정의한것 파일 관리 시스템에서 **파일** 에 해당된다.
**attribute:** 릴레이션의 열,(세로) 칼럼의 이름이나 데이터 항목, 파일 관리 시스템 관점에서 **필드** 에 해당.
**tuple:** 릴레이션의 행(가로) 즉 한사람 혹은 한사람의 항목 전체 실제 데이터 값. 파일 관리 시스템 구조에서 **레코드** 에 해당된다.
예시)회원이라는 릴레이션의 경우로 따져보자. 
회원명 주소
송중기 서울 강남
여기서 회원명과 주소 열은 속성. 송중기,서울 강남 하나하나는 투플인것.
****
**기본용어**
**도메인(Domain):** 하나의 속성이 가질 수있는 값의 범위. 예시)나이는 int:0~120. 주소는 문자열(char)
모든 값의 집합,입력 및 수정 할때 적합성의 판단 기준이 된다. 특성을 고려한 데이터 타입으로 결정한다.
**Null:** 속성값을 아직 모르거나 해당 없음을 표시한다.
**degree차수:** 하나의 릴레이션에서 속성(열-세로) 의 개수.
**cardinality 카디널리티:** 릴레이션에서 투플(행-가로)의 개수.
예시) 회원(회원id,이름,주소) -> 차수 =3.
만약 거기에 입력된 회원이 100명이라면 카디널리티=100.
****
실제 dbms에서는 릴레이션이라는 용어보다는 테이블이라는 단어가 더욱 자주 쓰입니다 도르.
**릴레이션 스키마(relation schema):** 릴레이션의 논리적 구조. 릴레이션의 이름과 속성(열-세로)를 정의한다.
예시)고객(고객ID,이름,주소,전화번호) 또다른 말로 **내포(relatin intension)** 이라고 부른다.
자주 바뀌지 않는 정적인 구조다.
**릴레이션 인스턴스(relation instance):** 어느 한시점에 릴레이션에 존재하는 투플(행-가로)들의 집합.
예시)오늘 입력된 고객 데이터. 또다른 말로는 **relation extension(외연)** 이라고 부른다. 
자주 바뀌는 동적인 데이터 이다.
예시)book(isdn(밑줄),name,price,pubdate,page) 와 같이 표현한다면.
릴레이션의 이름: book 
속성:isdn,name,price,pubdate,page.
차수 dgree:5개의 속성이니 5개.
이처럼 스키마가 틀이면 그틀에 따라 데이터(투플)이 들어갑니다. 
****
외연(extension) 이라고 불리는 인스턴스는 오늘 입력된 고겍 데이터 처럼 어느 한시점에 들어가는 릴레이션의 내용 또는 상태를 의미한다. 즉 투플은 전체데이터.
즉 각행(가로)는 투플.
테이블의 전체 행 개수는 카디널리티
111-22 파이썬책 20000
222-22 자바책 250000  이러한 경우 카디널리티는 2개인것.
****
**데이터베이스 스키마(database schema):** 여러 릴레이션 스키마의 모음. 즉 데이터 베이스의 전체구조(설계도).
**데이터베이스 인스턴스(database instance):** 여러 릴레이션 인스턴스들의 모음, 현재시점에 데이터 베이스에 들어가 있는 전체 데이터.
스키마= 건물의 설계도.
인스턴스= 실제로 사람들이 들어가 사는 건물 상태.
****
관계형 데이터 모델에서 릴레이션은 4가지 특성을 가진다.
**투플의 유일성** -모든 행 투플은 서로 달라야한다. 즉 중복된 데이터 행이 허용되지 않는다. 이를 구별하기 위해 기본 키를 설정한다.
**투플의 무순서성** -행의 순서에는 의미가 없다. 즉 하나의 릴레이션에서 투플간의 순서는 의미가 없다. 홍길동이 먼저 들어가든,양금명이 먼저 들어가든.
**속성의 원자성** -릴레이션의 열의 순서에도 의미가 없다 도서명,도서번호 가격 == 도서번호,도서명,가격
**속성의 무순서성** -속성(열-세로) 값은 더이상 나눌수가 없는 원자 값이여야 한다. 취미=독서,영화 이렇게 두가지는 안된다 이말이야. 물론 다중값 속성 제외.
****
e-r에서 관계 설계로의 변환.
**설계단계:** 어떤 정보 저장? 어떤 관계 맺기? 어떤 제약조건 필요?
**구현단계:** 설계한 e-r모델을 실제로 **릴레이션(테이블)** 로 변환한다. 즉 각각 대응되는 테이블로 바꾸는작업.
****
엔티티->릴레이션으로 변환,일반적인(즉week가아닌) 엔티티 집합은 그대로 새 릴레이션으로 만듬.
엔티티의 속성은 말그대로 릴레이션의 속성이 된다. 예시) 엔티티-학생(학번,이름,학과) -> 학생(학번,이름,학과).
관계성->릴레이션: 관계성r에 연결된 엔티티의 집합들 즉 관계에 참여하는 엔티티들의 기본 키를 이용해 새 릴레이션을 만듬 , 관계가 속성을 가질 경우->해당 속성도 포함.
예시)수강(학생 ,과목 ,성적) -> 수강(학번,과목코드,성적)
****
릴레이션의 결합
다대일 관계성을 예시로 들어보자 엔티티s{s key,s2} -r(skey,r1,tkey) -엔티티t{tkey,t2} =  s{skey, s2,r1} t{tkey,t2} 이런식으로 변환 가능. 
일대일 관계성을 예시로 들어보자 엔티티s{s key,s2} -r(skey,r1,tkey) -엔티티t{tkey,t2} = st={skey,s2,tkey,t2,r1} 이런식으로 변환가능. 
다대다는 중복이 발생하니 하지말도록 하자.
****
다수의 엔티티를 연결하는 관계성도 약한 엔티티로 구성이 가능하다. 이중마름모로 star-of 이런식. 
****
관계데이터 모델의 개념
식별자 - 키 투플을 유일하게 식별하는 속성또는 속성들의 집합. 
데이터 모딩 물리적db
주 식별자 -> 기본키
외래 식별자->외래키
보조식별자-)대체키 
****
키의 특성. 
유일성:하나의 릴레이션에서 모든 투플은 서로 다른 키값을 가져야함
최소소성 키를 구성하는 속성은 최소한으로!
슈퍼키:유일성을 만족하는 속성또는 속성들의 집합
후보키candiate:유일성+최소성.
기본키:후보키 중에서 기본적으로 사용되기 위해 선택된 키.
예시)릴레이션:고객(고객id,이름,주소)
슈퍼키: 고객id/고객 id,이름/이름,주소
후보키: 고객id/(이름,주소)
기본키: 고객id
****
기본키:기본적으로 사용되기 위해 선택된 키,일반적으로 정보를 검색하는 기준.중복된 튜플이 입력되는것을 방지.외래키에서 참조대상이됨.
기본키 고려사항: 널 불허,변하지 않는값,단순한 키 
대체키: 후보키중에서 기본키로 선택되지 않은 키.
외래키:다른 릴레이션의 기본키를 참조.
****
외래키 속성과 기본키 속성의 이름은 달라도 된다. 
하지만 도메인의 의미는 같아야한다.
****
외래키는 자기 자신을 참조가능. 같은 릴레이션의 기본키도 참조 가능 널값을 가질수도 있음.
****
무결성 제약 조건:데이터에 결함이 없이 데이터가 정확하고 유효하게 유지된 상태.
개체 무결성 제약조건:기본키를 구성하는 모든 속성은 널값을 가질수 없다.
참조 무결성 제약조건:외래키는 널값이 들어갈수 있음. 참조할수 없는 값을 가질수 없음.
