systems calls(시스템 호출)-운영체제 서비스에 접근할수 있도록 해주는 프로그래밍 인터페이스다.
고급언어 c,c++ 보통 api로 접근 (직접 시스템 호출 x) 주요 api=win32,posix,java.
api=표준화된인터페이스. 프로그램이 api를 호출->api는 내부적으로 시스템 호출을 호출 ->api를 통해 프로그램은 윤영체제 내부 사항을 몰라도 시스템 기능 활용 가능.
ex) printf -> write()-> 운영체제가 콘솔에 출력.
****
시스템 호출 구현.
각 system call 에는 고유한 번호가 있다.
커널은 이 번호를 system calls table 을 통해 찾아 호출한다. 호출 결과를 호출자에게 반환한다.
사용자는 구현 방식을 몰라도 api를 통해 시스템 호출 사용가능.
즉 api 인터페이스고 실제처리는 커널이 수행한다.
****
api->system call -os relationship 설명.
어플리케이션(사용자 프로그램)->api 시스템 콜 호출 ex)open() 이러면 유저 모드에서 커널모드로 간다. systems call interface= 내부적으로 open(),implementation system call. 그리고 결과 값 return 을 사용자에게 전달.
****
system calls Parameter passing 시스템 호출의 매개변수 전달 방법.
단순히 어떤 함수를 호출하는것 이상으로 매개변수를 전달해야함.
세가지 주요 전달 방법-레지스터 방식: 레지스터에 직접 전달. 빠르지만 레지스터 수에 제한.
                     메모리 블록 방식: 매개변수를 메모리에 저장하고 해당 주소만 레지스터에 전달. 리눅스 솔라리스가 사용
                     스택방식: 스택에 매개변수를 os가 push,pop 하는 방식. 매개변수 개수에 제한 없음.
****
메모리 블록 방식.
유저 프로그램이 여러 매개 변수를 테이블 블록에 저장. 이 블록의 주소를 레지스터를 통해 커널로 전달. 운영체제는 이주소를 통해 블록안의 모든 값에 접근 가능 커널 넘버 system cal1 13 이런식으로 주소가 넘어옴.

운영체제 구조
단순구조:ms dos. 모듈 분리 부족.모듈화 되어 있지 않음.경계 불문명 모두 하나의 공간.
more complex 복잡한 구조: unix 사용자-커널 구분은 있지만 완전히 계층적이진 않음. 하드웨어 제약으로 제한적인 구조 시스템프로그램과 커널 구조. 하나의 큰 커널이 다양한 기능을 한층에 몰아서 처리. 시스템 프로그램에는 :명령어, 컴파일러,응용프로그램.셸. 커널레벨에는 그외에 전부. 파일시스템,터미널 신호 조작,시피유 스케쥴링.
Layered(계층구조):운영체제를 여러 계층으로 나누어 구조화.
레이어 0: 하드웨어 레이어N:사용자 인터페이스 모듈화,특정계층만 수정가능으로 유연성 증가.
그러나 각계층간 통신이 필요해서 성능저하 가능. 설계 복잡,계층 나누기 어려움.

MicroKernel(마이크로 커널 구조):핵심기능만 커널에 두고 나머지는 사용자 공간으로 이동.
운영체제 커널에서 필수기능만 유지 나머지는 사용자 공간. MACH커널. 핵심 기능 만 커널에 유지.
커널이 작아 안전성과 보안성 높음 새로운 기능 추가 쉬움,다양한 하드웨어에 이식용이 그러나  커널<->사용자 공간간 빈번한 메세지 전달로 성능 저하 가능성 존재.
