## ch04 동시성 쓰레드 

왜 멀티스레드가 중요한가:현 어플리케이션 대부분이 멀티스레드 기반
멀티스레드는 다양한 작업을 병렬로 수행가능.
프로세스 생성보다 훨씬 가볍다.
코드가 단순하고 효율성이 증가
커널 자체도 멀티스레딩 구조로 설계되었다.
****
동시성:하나의 cpu에서 여러작업 동시 진행. 
마치 한식당(프로세스) 여러 서빙직원(스레드).

멀티스레드 이점
반응성 리스펀시브: 일부작업이 막혀도 나머지 스레드는 계속 실행
자원 공유  리소스 쉐어링: 스레드 같은 프로세스내 자원 공유하므로 공유메모리나 메시지 패싱보다 구현간단.
경제성 이코노미:프로세스보다 스레드를 생성.전환하는 비용이 낮음 즉 contxt보다 쓰레드가 더저렴하다.
확장장성 스카빌리티:멀티프로세서 시스템에서 스레드들이 병렬로 실행되며 성능 향상이 가능함.
****
멀티코어 시스템에서의 도전과제 
dividing activites(작업 분할) 전체 작업을 병렬화 하기위해 나누는 과정
balance (균형배분): 각코어에 동일한양의 일을 할당해야함
data splitting (데이터 분할):코어들이 동시에 작업할수 있도록 데이터를 나누어야함
data dependensy(데이터 의존성):여러 스레드가 같은 데이터 접근.수정시 충돌 방지.
testing and debuging
parallelism:다중 작업을 실제로 동시에 실행
concurrency:다중작업이 동시에 실행되는것 처럼 보이게함.
****
병렬성의 두가지 유형 데이터,task(작업): 동일한 데이터를 나누기 or 서로다른 작업 각 스레드에 분배. 
parallelism:여러코어에서 실제로 동시에 작업수행 멀티코어 cpu->여러 스레드 동시 실행.
concurerency:단일 코어에서 여러 작업이 동시에 진행되는것처럼 보인 os->시간 단위.
****
싱글 스레드:하나의 실행 흐름만 존재.하나가 멈추면 전체 정치.
멀티 스레드:여러 실행흐름을 병렬로 진행 하나가 멈춰도 나머지는 계속 실행가능.
****
유저스레드: os커널이 아닌 사용자 라이브러리 수준에서 관리.
커널 스레드:os커널이 직접 생성,스케즐
유닉스 기반 표즌 스레드 포터블 오퍼레이팅 시스템 인터페이스 유닉스 :posix pthreads.
멀티 스레드 모델 개요
many-to-one 많은 사용자 스레드를 하나의 커널스레드에 매핑  병령성 없음 병목발새 쉬움 멀티코어 병렬 처리 불가능 
one-to-one 사용자 스레드 마다 하나의 커널 스레드 매핑하는 구조 진정한 병렬실행 가능 그만큼 오버해드 증가 스레드 많이 만들면 발생.
many-to-many 많은 사용자 스레드를 여러 커널 스레드에 매핑 유연한 병렬처리가능 동시에 여러 스레드 실행가능 오버헤드 적절하겍 제어됨.
유저레벨 스레드는 프로그램이 만들고 관리함
커널 스레드는 os가 스케줄링함.
****
two-level=m:M 기반이지만 특정사용자 스레드를 커널스레드에 고정할수있음. 
****
스레드 라이브러리: 프로그래머가 직접 사용할수 있도록 제공되는 api,스레드 생성/관리 기능을 포함한다.
유저레벨:커널은 인식하지 못하고 사용자 공간에서만 관리,빠르지만 병목 발생 가능.
커널 서포트:커널이 스레드 생성과 스케줄링 지원,안정적이지마 다소 무거움
예시)posix pthread. pthread 유저공간 라이브러리에 저장된 api다 
현대 os는 리눅스는 이 pthread를 커널스레드로 매핑한다.
pthread는 api명세만 존재하며 주로 유닉스의 운영체제에서 사용된다. 스레드의 생성및 동기화를 제공한다. 싱크로지네이션.
****
implicit 스레딩 암시적 스레딩:컴파일러나 라이브러리 자동으로 스레드 생성 처리하는 방식. 명시적 스레드는 버그가 많고 디버깅이 어렵기 때문.
****
스레드 pool 미리 일정수의 스레드를 생성해 풀에 보관,요청이 들어오면 스레드를 다시 꺼내 다시 보관 마치 pcb 처럼 속도항상,저원관리 전략 다양화. 스레드 만드는것보다 빠르고 개수제한으로 과부화 방지 작업을 예약하거나,주기적으로 수행가능. 
****
멀티 스레드 환경에서 의 중요이슈
fork exec 어느 스레드중 어느스레드를 복사할지
신호 핸들링 어느스레드가 신호를 받을지
스레드 캔슬 강제종료할지 안전하게 종료할지
쓰레드 로컬 스토리지 스레드마다 독립적인 변수 필요시 사용.
스케쥴러 엑티비젼 사용자 스레드 <->커널스레드간 효율적 연결을 위한 기술.

신호처리 전략 :해당 스레드 모든 스레드 일부 스레드 전달,특정 스레드 지정 

lwp:가벼운 무게 즉 가상프로세서
