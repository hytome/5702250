프로세스간 통신.
process:호스트 내에서 실행되는 프로그램.
동일한 호스트 내에서는 os가 제공하는 프로세스간 통신을 이용한다.
서로 다른 호스트라면? ->메세지 교환을 통해 통신한다.
클라이언트 프로세스: 통신을 시작하는 프로세스.
서버 프로세스:상대가 접속하기를 기다리는 프로세스.
P2P:이 아키텍쳐 어플리케이션도 클라이언트,서버 프로세스 모두 가질 수 있음.
프로세스:호스트에서 실행되는 단위 같은 호스트->IPC. 다른 호스트->메시지 교환.

Sockets:프로세스는 자체 소켓을 통해 메시지를 송수신. 소켓은 문에 비유할수 있음.
소켓:프로세스와 네트워크를 연결하는 end point로 운영체제에서 제공한다.
프로그램은 소켓을 통해 메시지를 내보내고(push). 네트워크 전송 계층에 맡기는것.

프로세스 간 주소 지정 Addressing processes.
메시지를 수신하려면 프로세스에 idntifier가 필요하다.
프로세스 식별자에는 ip주소 뿐만 아니라 해당 호스트 내 프로세스에 할당된 포트 번호도 포함된다.
즉 메세지를 보내려면 식별자 = IP주소+포트번호.
->이걸로 호스트 내 여러 프로세스 구별가능.

공개프로토콜:RFC로 정의 되어 누구나 접근 가능하다. 독점 프로토콜:스카이프 같이 소유권이 있는 프로토콜.

-timing 타이밍. -낮은 지연

데이터 전송 서비스.
어플리케이션 마다 데이터 손실을 허용하지 않거나 어떤것은 약간 허용한다.
유튜브 스트리밍:약간의 프레임 손실은 감수하지만,끝임없는 재생이 중요하다.
이메일 전송: 약간 느려도 상관없지만,데이터 손실은 절대 안된다.
****
TCP 서비스 (Transmisson Control Protocol)
-Reliavble TransPort 신뢰성 있는 전송. 데이터 손실 발생시 자동으로 재전송함.
-flowControl 흐름제어,송신자가 수신자의 처리 능력이 초과하지 않도록 제어.
-congenstion control 네트워크가 과부화 상태에 들어가면 송신속도 조절.
-그러나 제공하지 않는것:타이밍,최소 처리량 보장. 보안. 언제까지 전송해라 몇 mbps를 보장해라 이런거..
-연결지향: 클라이언트와 서버 프로세스간 연결 설정 필요.

패킷이 좀 떨어져도 다시보내기보다 실시간 유지가 중요. 실시간 스트리밍,온라인게임

http는 두가지의 타입이 있다.
비지속성:tcp연결 하나당 최대 하나의 객체.
지속성 tcp:하나의  tcp 연결을 통해 클라이언트와 서버가 여러 객체 전송가능.
비지속성(1.0):객체 하나 요청할때마다 새tcp 연결
지속성(1.1):tcp연결을 유지하여 여러 요청 응답 주고받음.

RTT(Round trip time)클라이언트에서 서버로 서버에서 클라이언트로 패킷이 왕복하는데 걸리는 시간.
비지속성 http는 파일 하나를 받을때 최소 두번 왕복해야합니다. rtt가 100ms 이면 요청/응답 100ms+ tcp 연결 100ms=200ms 가 됩니다. 즉 2RTT+파일전송시간.
왜?매번 새 tcp 연결을 해야하니까.
공식 =2RTT+파일 트렌스 미션 타임
