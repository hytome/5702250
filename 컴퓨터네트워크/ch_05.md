## ch_05. rdt 3.0~
rdt3.0 – 오류 및 손실 채널 가정.
새로운 채널 가정: 기본 채널에서 패킷(데이터, ACK) 손실도 발생할 수 있음
• 체크섬, 순서 번호(seq #), ACK, 재전송이 도움이 되긴 하지만… 완벽하진 않음
기존 rdt2.x에서는 “잡음에 의한 비트 오류”만 다뤘다면, rdt3.0부터는 **손실(loss)**까지 고려합니다.

사람의 대화처럼 “다시 말해 달라”“잘 들렸어?” 같은 확인 절차가 필요함을 시사합니다.

예시: 전화 통화에서 잡음으로 누락된 단어를 “다시 한 번 말씀해 주세요”라고 요청하는 과정과 유사합니다.
****
접근법: 송신자는 ACK를 합리적인 시간만큼 기다림  
▪ 해당 시간 내 ACK 미수신 시 재전송  
▪ 만약 지연(delayed)된 경우 재전송 패킷이 중복되지만, 순서 번호(seq #)가 이를 해결  
   • 수신자는 ACK에 **어떤 seq #**을 확인했는지 반드시 포함해야 함

타임아웃(timeout)
▪ 카운트다운 타이머를 사용해 일정 시간이 지나면 인터럽트
Retransmission Timeout(RTO) 기법: 일정 시간(예: RTT 값 기반) 후 ACK가 없으면 패킷을 다시 보냅니다.

예시: 택배 배송 확인 문자(“배송 완료”)가 일정 시간 안 오면 자동 재요청하는 시스템과 유사합니다.
****
rdt3.0 송신자 FSM

1. ACK0 대기 상태  
   - seq 0 패킷 생성(make_pkt) → 전송(udt_send) → 타이머 시작(start_timer)  
2. 상위 계층 호출(call 1) 시  
   - seq 1 패킷 생성/전송 → 타이머 시작  
3. 수신된 ACK0/ACK1 확인 시  
   - 손상 없으면(stop_timer) 타이머 중지 → 다음 상태로 전이  
예시: 신용카드 결제에서 “승인 응답”이 올 때까지 기다리고, 응답이 없으면 결제 요청을 다시 보내는 흐름과 유사합니다.
****
타임아웃 발생 시
  • 동일 패킷 재전송(udt_send)
  • 타이머 재시작(start_timer)

수신된 패킷이 손상됐거나 기대치와 다른 ACK일 때도 재전송
예시: 자동화된 서버 헬스체크에서 응답이 없으면 재시도를 수행하는 방식과 동일합니다.
****
예시: 이메일을 보냈을 때 서버와 클라이언트가 매번 “전송됨/수신됨” 확인 메시지를 주고받는 경우와 같습니다.
****
rdt3.0 동작 예시 (Loss & Delay)
(b) 패킷 손실: pkt1이 손실되면, ACK 미수신으로 타임아웃 발생 후 pkt1 재전송.

(c) ACK 손실: ACK1이 손실돼도 송신자는 타임아웃 후 pkt1 재전송, 수신자는 중복 감지 후 재응답.

(d) 조기 타임아웃/지연 ACK: ACK이 늦게 도착할 때도 송신자는 타임아웃 후 재전송하지만, 수신자는 중복으로 판단하여 처리합니다.

예시: 스마트폰 메시지가 네트워크 문제로 유실되거나 확인 읽음 표시가 늦게 뜰 때, 앱이 자동 재시도를 하는 동작과 유사합니다.
****
​rdt3.0 성능 (Stop-and-Wait Utilization)
예시: 1 Gbps 링크, 전파 지연 15 ms, 패킷 크기 8000 비트  

전송 지연(Transmission Delay) Dtrans = L/R = 8000 bits ÷ 10^9 bits/s = 8 μs  

송신자 활용도 Usender = Dtrans / (RTT + Dtrans)  
                     = 8 μs / (30 ms + 8 μs) ≈ 0.00027 (0.027%)
송신자 활용도가 0.027%에 불과해, 채널 대역폭의 대부분이 유휴 상태로 낭비됩니다.

이는 stop-and-wait 프로토콜의 근본적 한계로, 고속·장거리 링크에서는 성능이 크게 떨어집니다.

예시: 고속도로를 1차선으로만 운영해 교통 정체가 심한 것과 유사합니다.
****
타임라인 다이어 그램.
첫 비트 전송 시각 t = 0  
…  
ACK 도착 후 다음 패킷 전송, 시각 t = RTT + 전송 지연(L/R)
타임라인에서, 패킷 전송 → 왕복 시간 기다림 → ACK 도착 → 다음 전송 이 반복됩니다.

예시: 택배가 배달된 뒤 “배송 완료” 알림을 받고야 다음 택배를 보내는 과정과 동일합니다.
****
rdt3.0 활용도 공식 재정리
Usender = (L/R) / (RTT + L/R) ≈ 0.00027  
****
rdt3.0 – 파이프라이닝 프로토콜 동작
stop-and-wait의 비효율을 해결하기 위해, 파이프라이닝은 여러 패킷을 연속 전송하며 ACK를 기다립니다.

이를 위해 seq # 공간을 넓혀(예: 07 대신 015) 각 패킷을 구분하고, 송신자/수신자 모두 받은 패킷을 임시 저장(bufffer)합니다.

예시: 공장 자동화 라인에서 여러 공정을 동시에 가동하는 것처럼, 네트워크도 “여러 패킷”을 한 번에 굴려 처리 효율을 높입니다.
****
3-패킷 파이프라이닝은 송신자 활용도를 3배로 증가시킵니다!

U_sender = (3 × (L/R)) ÷ (RTT + (L/R))
****
 Go-Back-N 동작 예시
 송신: pkt0, pkt1, pkt2, pkt3 전송  
…  
pkt2 손실 → timeout 발생 → pkt2와 이후 모든 패킷(pkt3, pkt4, pkt5) 재전송
pkt2가 유실되면, 송신자는 “2번부터 끝까지” 모두 다시 보내 Go-Back-N 동작을 보입니다.

예시: 컨베이어 벨트에서 2번째 제품이 빠지면, 2번 이후 모든 제품을 다시 포장해 내보내는 식입니다.
****
Selective Repeat(선택적 재전송)
Selective Repeat는 Go-Back-N의 “한꺼번에 재전송” 대신, 누락된 것만 골라서 재전송하여 효율을 높입니다.

예시: 이메일 첨부파일 중 손상된 페이지만 다시 보내는 방식과 비슷합니다.
****
