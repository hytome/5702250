## ch_07 네트워크 계층: 목표
NAT:Network Address Translation.
****
네트워크 에리어.services and protocols
송신 호스트에서 수신 호스트로 전송 계층(segment)을 전달  
  • 송신자: 세그먼트를 데이터그램(datagram)으로 캡슐화하여 링크 계층으로 전달  
  • 수신자: 데이터그램을 수신 후 세그먼트를 전송 계층 프로토콜에 전달  
모든 인터넷 장치(호스트, 라우터)에 네트워크 계층 프로토콜 존재  
  • 통과하는 모든 IP 데이터그램 헤더 검사  
  • 입력 포트(input port)에서 출력 포트(output port)로 옮겨 end-to-end 경로 전송.
캡슐화/역캡슐화: TCP 세그먼트를 IP 데이터그램에 담았다가, 수신 측에서 다시 분리합니다.
라우터 동작: 각 입력 포트의 패킷 헤더를 보고 적절한 출력 포트로 전송합니다.
예시: ISP 라우터가 고객 가정에서 온 IP 패킷을 인터넷 백본으로 전달하는 과정입니다.
****
네트워크 계층의 두 가지 핵심 기능.
 포워딩(forwarding): 라우터 입력 링크(input link)에서 적절한 출력 링크(output link)로 패킷 이동  
비유: 한 교차로(interchange)를 지나는 과정
 라우팅(routing): 출발지에서 목적지까지 경로를 계획하는 과정  
   • 라우팅 알고리즘(routing algorithms)
포워딩은 각 라우터 내부에서의 단일 홉(hop) 처리, 라우팅은 전체 경로 계산입니다.
예시: 여행에 비유하면, 포워딩은 고속도로 톨게이트 하나를 지나는 것이고, 라우팅은 출발지에서 목적지까지 어느 길을 탈지 미리 정하는 계획 단계입니다.
****
데이터 플레인,제어 플레인. data plane,control plane.
데이터 플레인은 각 라우터에서 수신된 패킷을 즉시 포워딩하는 기능입니다. 
라우터별 로컬 기능

예시: 지하철 역에서 들어온 승객을 바로 간판에 따라 해당 플랫폼으로 안내하는 과정

제어 플레인은 전체 네트워크의 경로를 설정하고 업데이트하는 기능입니다.
네트워크 전체 로직.
예시: 도시의 지하철 노선도를 설계해 어떤 역을 거쳐 목적지에 갈지 결정하는 과정
****
개별 라우터의 제어 플레인
전통적인 방식에서는 각 라우터가 독립적으로 라우팅 알고리즘을 실행하며 주변 라우터와 정보를 교환합니다.

예시: 서로 다른 로컬 버스 정류장이 인근 정류장과 실시간으로 버스 배차 정보를 교환해 경로를 조정하는 시스템
****
Software-Defined Networking.
SDN은 중앙 컨트롤러가 네트워크 전반의 경로를 계산하고, 라우터에는 단순히 포워딩 테이블만 설치하도록 분리된 구조입니다.

예시: 교통 관제 센터가 도시 전체 교통 신호를 중앙에서 제어하고, 각 교차로에는 신호등 설정만 내려주는 시스템
****
네트워크 서비스 모델 예시
개별 데이터그램에 대한 서비스 예시:
 보장된 전달(Guaranteed Delivery)  
 40 ms 이하 지연 보장(Guaranteed <40 ms Delay)
 예시: 금융 거래 네트워크에서 트랜잭션 메시지의 40 ms 내 전달 보장
데이터그램 흐름에 대한 서비스 예시:
순서 보장 전달(In-order Delivery)  
 최소 대역폭 보장(Guaranteed Minimum Bandwidth)  
 패킷 간 간격 변화 제한(Inter-packet Spacing Constraints)
 예시: 실시간 오디오 스트리밍에서 최소 100 kbps 대역폭과 일정한 패킷 간격 유지
****
네트워크 구조 | 서비스 모델 | 대역폭 | 손실 | 순서 | 타이밍
Internet | Best Effort (최선 노력) | 보장 없음 | 보장 안 됨 | 보장 안 됨 | 보장 안 됨
ATM | CBR (Constant Bit Rate) | 일정한 대역폭 | 보장 | 보장 | 보장
ATM | ABR (Available Bit Rate) | 가능한 대역폭 | 가능 | 보장 안 됨 | 보장 안 됨
Internet | IntServ Guaranteed (RFC 1633) | 최소 대역폭 보장 | 보장 | 보장 | 보장
Internet | DiffServ (RFC 2475) | 가능 | 가능 | 가능 | 보장 안 됨
****
Best-Effort 서비스 회고
단순한 메커니즘 덕분에 인터넷이 널리 채택·배포될 수 있었음  
충분한 대역폭 확보로 실시간 애플리케이션(예: VoIP, 비디오)의 성능이 “대부분의 경우” 충분히 양호  
애플리케이션 계층의 분산 서비스(데이터센터, CDN)를 클라이언트 네트워크 근처에 배치해 다중 위치에서 서비스 제공 가능  
“탄력적(elastic)” 서비스의 혼잡 제어가 도움  
CDN: Content Distribution Network
단순성: 복잡한 QoS 보장 없이도 전 세계로 확장된 인터넷의 성장 비결

분산 인프라: CDN처럼 여러 지역에 서버를 두어, 사용자와 가까운 곳에서 콘텐츠를 전송해 지연을 최소화

실시간 앱: 대역폭이 충분하면 패킷 손실·지연이 약간 있어도 VoIP나 비디오 콜이 “거의 항상” 원활히 동작

예시: 유튜브가 세계 각지에 캐시 서버를 두고 사용자 요청을 처리하는 방식이 바로 이 모델의 전형입니다.

라우터 아키텍쳐 개요.
스위칭 패브릭: 여러 입력 포트에서 도착한 패킷을 빠르게 원하는 출력 포트로 연결하는 하드웨어
Switching Fabric
라우팅 프로세서: 포워딩 테이블을 계산·관리하는 소프트웨어
Routing Processor
예시: 공항의 Baggage Handling System에서 짐을 나르는 컨베이어(스위칭 패브릭)와, 표를 확인하고 탑승구를 결정하는 관제(라우팅 프로세서)를 분리한 구조와 유사합니다.
****
Input port functions
입력 포트 기능.
line termination: 물리 계층 장치가 전기적 신호를 비트 스트림으로 변환

match+action: 헤더(예: IP 목적지 주소)를 메모리의 테이블과 비교해, 어떤 출력 포트로 보낼지 결정

예시: 초고속 열차 터널 입구에서 터널 통과 여부를 신호등으로 제어하는 과정과 유사합니다.
****
일반화된 포워딩(decentralized switching)
전통적 포워딩은 IP 주소만 보고 패킷을 넘겨주지만, 일반화된 포워딩은 VLAN 태그, QoS 우선순위 등 다양한 헤더를 활용할 수 있습니다.
예시: 물류 센터에서 목적지 외에도 무게·취급 등급을 보고 분류·배송 경로를 결정하는 방식과 유사합니다.
****
가장 긴 접두사 매칭 소개 (Longest Prefix Matching)
IP 주소는 비트열이므로, 여러 테이블 엔트리가 일치할 수 있을 때는 가장 긴(구체적인) 접두사가 우선됩니다.
테이블에 192.168.0.0/16과 192.168.1.0/24가 모두 있을 때,

목적지 192.168.1.5는 /24(길이 24비트)가 /16보다 더 구체적이므로 /24 엔트리를 선택합니다.
****
테스트 주소(00011000…)는 두 번째 항목(/23)과 가장 긴(=가장 구체적인) 접두사가 일치하므로 인터페이스 1로 포워딩됩니다.
앞의 세 접두사 중 어느 것과도 일치하지 않으므로, **기본 경로(default route)**인 인터페이스 3(“otherwise”)로 포워딩됩니다.
****
접두사 매칭 HW 가속 – TCAM
TCAM: Ternary Content Addressable Memory
TCAM은 “0,1,×(don't care)”를 저장할 수 있어, 접두사 길이와 상관없이 매우 빠르게 매칭합니다.

예시: 대규모 ISP 라우터에서 수백만 엔트리 검색을 수십 나노초 내에 처리합니다.
****
 Switching Fabric
 스위칭 패브릭은 라우터 내부에서 패킷을 입력 포트에서 적절한 출력 포트로 옮기는 핵심 하드웨어입니다.

이상적으로 모든 포트가 동시에 최대 속도로 패킷을 주고받을 수 있어야 하므로, “N×라인 속도”를 목표로 설계합니다.
스위칭 속도(switching rate): 입력에서 출력으로 패킷을 전달하는 속도  
예시: 4포트 10 Gbps 라우터라면, 패브릭은 이론상 40 Gbps를 처리해야 합니다.
****
 Switching Fabric 유형 3가지.
 버스 방식: 모든 패킷이 공유 버스를 통과하며, 단순하지만 버스 대역폭 한계가 있음.

메모리 방식: 패킷을 시스템 메모리에 쓰고, 다시 읽어 전송. 메모리 대역폭에 제약.

상호 연결망: 크로스바·멀티스테이지(Clos) 스위치 등 병렬 연결로 높은 처리량을 달성.
Interconnection network
버스: 하나의 도로(버스)로 모두 지나가야 하는 왕복차로

메모리: 중앙 창고에 물건을 넣었다 꺼내 배송

인터커넥션: 여러 차선 고속도로 네트워크
****
메모리 기반 스위칭

1세대 라우터:
 • CPU가 직접 스위칭 제어  
 • 패킷을 시스템 메모리에 복사 후 전송  
 • 메모리 대역폭에 제약(데이터그램당 버스 왕복 2회)
****
버스 기반 스위칭

입력 포트 메모리 → 공유 버스 → 출력 포트 메모리로 데이터그램 복사  
 • 버스 경합(bus contention): 버스 대역폭이 스위칭 속도 한계  
 • 예: 32 Gbps 버스(Cisco 5600)로 액세스 라우터용 충분한 처리량
 예시: 지하철 승강장에서 하나의 통로만 있어 승객이 몰릴 때 지연이 생기는 구조.
 ****
 인터커넥션 네트워크 스위칭

크로스바(crossbar), 멀티스테이지(Clos) 스위치 등은 다중 프로세서 연결용에서 유래

8×8 멀티스테이지 스위치(작은 스위치 조합)
3×3 크로스바 예시
 • 멀티스테이지: 여러 계층(stage)의 소형 스위치 결합하여 n×n 스위치 구현  
 • 병렬 처리:  
   – 입구에서 고정 길이 셀(cell)로 분할  
   – 패브릭을 통해 셀 단위 스위칭  
   – 출구에서 셀을 재조합
멀티스테이지 스위치는 병렬로 스위칭 경로를 제공해 높은 처리량을 달성합니다.

셀 기반 처리(cell-switching)는 고정 크기로 분할해 패브릭 내부 병목 없이 유연하게 라우팅합니다.

예시: 다수의 병목 분기점이 있는 고속도로와, 톨게이트를 셀 단위로 나눠 처리하는 자동결제 시스템의 결합과 비슷합니다.
****
입력 포트 큐잉 (Input Port Queuing)
스위칭 패브릭의 처리 속도가 입력 포트 총합보다 느리면 → 입력 포트 큐에 버퍼링이 발생할 수 있음  
• 입력 버퍼 오버플로우로 인한 큐잉 지연 및 패킷 손실 발생!

입력 포트 큐잉

출력 포트 경합: 한 번에 하나의 패킷만 전송 가능하므로, 뒤의 패킷이 블록됨

스위칭 패브릭

한 패킷 시간 후: 뒤따르던 패킷이 Head-of-Line(HOL) 블록을 경험함
HOL 블로킹은 큐 맨 앞(front)에 있는 패킷이 전송되지 않아 뒤에 있는 패킷 전체가 대기하는 현상입니다.

입력 포트가 초당 10 Gbps를 받는데 스위칭 패브릭이 8 Gbps만 처리하면, 초과분이 모두 입력 포트 큐에 쌓입니다.

예시: 슈퍼마켓 계산대 한 곳이 느리면, 그 앞에 줄 선 모든 손님이 계산을 못 하고 기다리는 것과 같습니다.
****
Output Port Queuing: Buffering & Drop Policy)
 스위칭 패브릭에서 들어오는 데이터그램이 출력 링크 전송 속도보다 빠르면 버퍼링 필요. 여유 버퍼 없을 때 어떤 패킷을 버릴지 결정하는 “드롭 정책” 설계
 드롭 정책 예:

Tail Drop(도착 패킷 폐기)

RED(Random Early Detection, 랜덤 조기 폐기)

스케줄링 예:

FCFS(First Come First Serve)

우선순위 스케줄링(Priority Scheduling)

예시: 비행기 이착륙 대기에서 “연착된 항공편”을 우선 보내야 하는지, “VIP 편”을 먼저 보내야 하는지 정책을 정하는 것과 비슷합니다.
****
Output Port Queuing: Diagram
스위칭 패브릭에서 출력 포트로 전달된 패킷은 버퍼에 저장된 뒤,

스케줄러가 대기열에서 다음 전송할 패킷을 선택해 출력 링크로 보냅니다.

큐잉 구간에서 대기열 길이가 길어지면 지연과 버퍼 오버플로우로 인한 손실이 발생합니다.

예시: 택시 승강장에서 차량이 도착 대기 후 순차 탑승하는 구조와 유사합니다.
****
